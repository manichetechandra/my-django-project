# لوحة الإدارة: كل الجداول بأربع دوال

::: intro
في Django كانت لوحة الإدارة جاهزة: سطور قليلة في ملف `admin.py` لكل جدول، فتظهر صفحات القائمة والإضافة والتعديل والحذف. في PHP لا يوجد شيء جاهز، فنبني لوحتنا بالفكرة نفسها: **نصف كل جدول في مصفوفة إعدادات**، ثم نكتب **محركاً واحداً** يقرأ الوصف ويبني منه الصفحات. النتيجة: 26 قسماً (السلايدر، والأخبار، والطلبة، والمستخدمون...) تخدمها أربع دوال فقط: القائمة، والإضافة، والتعديل، والحذف.
:::

## الفكرة: إعدادات بدل كود

لو كتبنا لكل جدول صفحاته الأربع بيدنا، لاحتجنا أكثر من مئة صفحة متشابهة، وكل تحسين (بحث، تصفية، حذف جماعي) يجب أن نكرره مئة مرة. بدل ذلك نصف الجدول:

```php وصف جدول السلايدر (مبسّط)
'sliders' => [
    'model'  => Slider::class,                  // النموذج (الفصل 12)
    'plural' => 'السلايدر',                      // عنوان القسم
    'list'   => ['image', 'title', 'is_active'], // أعمدة القائمة
    'fields' => [                                // حقول نموذج الإضافة والتعديل
        'title'     => ['type' => 'text', 'label' => 'العنوان'],
        'image'     => ['type' => 'image', 'label' => 'الصورة', 'dir' => 'slider'],
        'is_active' => ['type' => 'bool', 'label' => 'نشط'],
    ],
],
```

ويقرأ المحرك هذا الوصف فيعرف: في القائمة صورة مصغّرة وعنوان وعلامة صح أو خطأ، وفي النموذج حقل نص وحقل رفع صورة ومربع اختيار، وعند الحفظ يتحقق من الصورة ويرفعها إلى `uploads/slider/`. إضافة جدول جديد إلى اللوحة تعني إضافة وصف، لا كتابة صفحات.

## ملف الإعدادات

### مفاتيح القسم وأنواع الحقول

قبل الملف، هذان جدولان ترجع إليهما كلما احتجت. أولاً مفاتيح وصف القسم:

| المفتاح | معناه | مقابله في Django |
|---|---|---|
| `model` | صنف النموذج | `model` |
| `group` و `icon` | مجموعته في القائمة الجانبية، وأيقونته | — |
| `label` و `plural` | اسم السجل الواحد («خبر») واسم القسم («الأخبار») | `verbose_name` |
| `list` | أعمدة جدول القائمة | `list_display` |
| `links` | الأعمدة التي تفتح صفحة التعديل عند النقر | `list_display_links` |
| `editable` | أعمدة تُعدَّل مباشرة من القائمة | `list_editable` |
| `filters` | الفلاتر الجانبية | `list_filter` |
| `search` | أعمدة البحث | `search_fields` |
| `order_by` و `per_page` | الترتيب، وعدد السجلات في الصفحة | `ordering` و `list_per_page` |
| `actions` | إجراءات جماعية (نشر، تمييز...) | `actions` |
| `fields` | حقول نموذج الإضافة والتعديل | `fields` |
| `inlines` | صور أو وثائق مرتبطة تُدار داخل صفحة السجل | `inlines` |
| `columns` | أعمدة محسوبة ليست في الجدول | دوال في `list_display` |
| `badge` | عدد أحمر بجانب القسم في القائمة الجانبية | — |
| `view_url` | زر «عرض في الموقع» | `view_on_site` |
| `on_view` و `on_save` | دالة تُنفَّذ عند فتح سجل، وأخرى بعد حفظه | `save_model` |
| `can_add` و `can_edit` و `can_delete` | منع الإضافة أو التعديل أو الحذف | `has_add_permission`... |
| `hidden` | لا يظهر في القائمة الجانبية | — |
| `superuser_only` | للمدير العام فقط | — |

وثانياً أنواع الحقول، وما يصنعه المحرك لكل نوع:

| النوع | حقل الإدخال | التحقق والحفظ |
|---|---|---|
| `text` و `textarea` | سطر نصي، أو مربع نص متعدد الأسطر | الطول الأقصى `max` |
| `email` و `url` | بريد أو رابط (من اليسار لليمين) | صيغة صحيحة |
| `int` و `decimal` | رقم صحيح، أو رقم بمنزلتين | رقم، وحدود `min` |
| `bool` | مربع اختيار | 1 أو 0 |
| `select` | قائمة من خيارات النموذج (`$choices`، الفصل 11) | القيمة من الخيارات فقط |
| `fk` | قائمة بسجلات جدول آخر | السجل موجود فعلاً |
| `date` و `datetime` | منتقي تاريخ، أو تاريخ ووقت | تاريخ صالح |
| `image` و `file` | رفع ملف مع معاينة الحالي | الصنف `Upload` (الفصل 20) |
| `slug` | رابط يُملأ تلقائياً من العنوان | حروف وأرقام وشرطات |
| `color` و `icon` | منتقي لون، واسم أيقونة مع معاينتها | صيغة اللون |
| `password` | كلمة مرور (فارغة = بلا تغيير) | قواعد القوة، ثم التشفير |
| `readonly` | نص للعرض فقط | لا يُقرأ من النموذج أبداً |

## التجربة

1. افتح `http://localhost/dou-setif/admin/`: تُنقل إلى صفحة الدخول. ادخل بحساب المدير (الفصل 21) فتعود إلى اللوحة.
2. **شريحة جديدة** (وعد الفصل 15): «السلايدر» ← «إضافة صورة سلايدر»، واكتب عنواناً واختر صورة، ثم «حفظ». افتح الصفحة الرئيسية: الشريحة في السلايدر.
3. جرّب رفع ملف `.php` أو ملف نصي غيّرت امتداده إلى `.jpg` صورةً للشريحة: يرفضه `Upload` برسالة خطأ.
4. **ملف للتحميل** (وعد الفصل 20): «مركز التحميلات» ← «إضافة ملف»، وارفع PDF. في `/downloads/` اضغط «تحميل»: يبدأ التحميل ويزيد العداد في القائمة.
5. **كلمة مرور طالب** (وعد الفصل 21): «المستخدمون» ← اسم مستخدم الطالب (رقم تسجيله)، واكتب كلمة مرور جديدة واحفظ. يدخل الطالب بها، وتخرج جلساته القديمة.
6. «طلبات الطلاب» ← طلب معلق، وغيّر الحالة إلى «معتمد» واحفظ: يصل الطالب إشعار، ويُسجَّل اسمك مراجِعاً.
7. «رسائل اتصل بنا»: افتح رسالة جديدة، ثم ارجع: نقص العدد الأحمر بجانب القسم.
8. في «الأخبار»: صفِّ بـ «خبر مميز: نعم»، ثم ابحث بكلمة، ولاحظ الرابط: `?f_is_featured=1&q=...`. حدّد خبرين واختر «تحويل إلى مسودة».
9. أنشئ مستخدماً موظفاً (بلا «مدير عام») وادخل به: لا يرى «المستخدمون»، و`/admin/users/` تعطيه 404.

::: summary
- لوحة الإدارة **محرك عام** يقرأ وصف كل جدول من `admin_config.php`: أربع دوال (قائمة، إضافة، تعديل، حذف) تخدم 26 قسماً.
- الوصف يحدد الأعمدة والروابط والتعديل المباشر والفلاتر والبحث والإجراءات والحقول والملفات المرتبطة، والخطافات `on_view` و`on_save`.
- الأمان: الأسماء من الإعدادات لا من الرابط، والقيم معاملات، والحقول المعروضة فقط لا تُقرأ، والخيارات تُتحقق، والملفات يفحصها `Upload`، والحذف بـ POST فقط.
- الملفات: نحذف المرفوع للتو إن فشل الحفظ، والمستبدَل بعد النجاح، ولا نحذف ملفاً يستعمله سجل آخر.
- خدعة الحقل المخفي قبل المربع لمعرفة «ألغى التحديد»، و`$_FILES` لعدة ملفات قوائم خصائص لا قائمة ملفات.
:::
