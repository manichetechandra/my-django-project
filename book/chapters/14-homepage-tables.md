# جداول الصفحة الرئيسية

::: intro
الآن ننشئ قاعدة بيانات الموقع الحقيقية `dou_setif`، ونكتب أول جداولها: جدول لكل مصفوفة من مصفوفات الصفحة الرئيسية (السلايدر، الأخبار، النشاطات، الأقسام، الإقامات). نكتب الجداول في ملف `database/schema.sql` هو ملف **نهائي** من ملفات المشروع، ثم نملؤها ببيانات تجريبية هي نفسها محتوى مصفوفاتنا.
:::

## إنشاء قاعدة البيانات

1. افتح `http://localhost/phpmyadmin`.
2. اضغط **New** (جديد) في القائمة اليسرى.
3. اكتب اسم قاعدة البيانات: `dou_setif`.
4. اختر الترتيب (Collation): **utf8mb4_unicode_ci**.
5. اضغط **Create**.

أو نفّذ في تبويب SQL:

```sql مثال
CREATE DATABASE dou_setif CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

## الملف schema.sql

بدل إنشاء الجداول بالنقر، نكتب أوامرها في **ملف**: هكذا تبقى بنية قاعدة البيانات محفوظة مع المشروع، ونستطيع إعادة إنشائها على أي حاسوب أو استضافة في ثوانٍ. أنشئ في جذر المشروع مجلداً اسمه `database`، وداخله الملف `schema.sql`.

### جدول المستخدمين

أول جدول هو جدول **الحسابات**. لن نستعمله فعلياً قبل فضاء الطالب، لكننا نحتاجه الآن لأن جدول الأخبار يحفظ **كاتب** كل خبر برقم حسابه. اترك سطراً فارغاً بعد الرأس واكتب:

@file database/schema.sql 52-63,65-70

| العمود | دوره |
|---|---|
| `id` | الرقم التعريفي، يزيد تلقائياً |
| `username` | اسم الدخول، فريد (`UNIQUE KEY`، السطر 69). للطلبة هو رقم التسجيل الجامعي |
| `password` | كلمة المرور **مشفّرة** (سنرى كيف في الفصل 24)، و255 حرفاً تكفي لكل خوارزميات التشفير |
| `email`، `first_name`، `last_name` | البريد والاسم واللقب، بقيمة افتراضية فارغة |
| `is_staff` | موظف: يدخل لوحة متابعة الطلبات ولوحة التحكم |
| `is_superuser` | مدير عام: كل الصلاحيات |
| `is_active` | الحساب مفعّل؟ الحساب المعطّل لا يستطيع الدخول |
| `last_login`، `date_joined` | آخر دخول، وتاريخ التسجيل (تلقائياً: `CURRENT_TIMESTAMP` = الآن) |

`COMMENT '...'` ملاحظة نصية تُحفظ مع العمود وتظهر في phpMyAdmin، لا تؤثر على العمل. والسطر 64 المخطّط صلاحية خاصة بمسابقات التوظيف (`can_recruit`) نضيفها في الفصل 43.

### السلايدر والإحصائيات

@file database/schema.sql 72-104

قارن جدول **`sliders`** (الأسطر 75–92) بمصفوفة `$slider_images` من الفصل 11: الأعمدة `title` و`subtitle` و`image` هي مفاتيح المصفوفة نفسها، وأُضيفت أعمدة جديدة لم تكن في المصفوفة:

- `link` و`button_text`: رابط اختياري للشريحة ونص زر يظهر عليها (`NULL` و`''` افتراضياً: لا رابط ولا زر).
- `order`: رقم ترتيب الظهور، الأصغر أولاً. لاحظ العلامة `` ` `` حوله: `order` كلمة محجوزة في SQL (تذكّر `ORDER BY`).
- `is_active`: 1 تظهر، 0 مخفية. هكذا يُخفي المدير شريحة دون أن يحذفها.
- `created_at`: تاريخ الإضافة، تلقائياً.

### أعمدة اللغات: `_fr` و`_en`

لاحظ الأعمدة التي ينتهي اسمها بـ `_fr` و`_en`: `title_fr` و`title_en` بعد `title`، و`subtitle_fr` و`subtitle_en` بعد `subtitle`... موقعنا سيكون بثلاث لغات، فكل نص يكتبه المدير (عنوان، وصف، نص زر...) له ثلاث نسخ: **العربية** في العمود الأصلي `title`، و**الفرنسية** في `title_fr`، و**الإنجليزية** في `title_en`.

- العمود العربي إجباري (`NOT NULL`)، أما الترجمتان فاختياريتان (`NULL DEFAULT NULL`): إن كانت الترجمة فارغة يرى الزائر الفرنسي النص العربي بدل صفحة فارغة.
- الترجمات أطول قليلاً (`VARCHAR(300)` مقابل `VARCHAR(200)`)، لأن النص الفرنسي أطول عادة من أصله العربي.
- لا تُترجم إلا **النصوص**: الصورة والرابط والترتيب واحدة في كل اللغات.

سنعرض النسخة المناسبة للغة الزائر في الفصل 22، ويملؤها المدير من لوحة التحكم يدوياً أو بزر «ترجمة تلقائية» (الفصل 40). وستجد هذه الأعمدة في كل جداول المحتوى.

وجدول **`statistics`** (الأسطر 94–104): أرقام تعريفية (أيقونة، رقم، تسمية) يديرها المدير من لوحة التحكم، مثل «2000 سرير». الصفحة الرئيسية الحالية تعرض بدلها **إحصائيات الموقع** المحسوبة تلقائياً، لكن الجدول جزء من المشروع وسنحتاجه في الفصل 27.

### الأخبار

اترك سطراً فارغاً، واكتب جدول الأخبار:

@file database/schema.sql 163-192

::: note لماذا تقفز الأرقام من 87 إلى 126؟
في الملف النهائي توجد بين جدول `statistics` وجدول `news` ثلاثة جداول أخرى (كلمة المدير، الهيكل التنظيمي، تاريخ المديرية) لا نحتاجها الآن. سنكتبها في الفصلين 27 و28 بصناديق «**إدراج**»، فنضعها حينها **في مكانها** بين هذين الجدولين. الأرقام في الصناديق هي أرقام الملف النهائي؛ في ملفك ستكون أصغر الآن، ولا بأس. وكذلك القفزات القادمة بين الجداول.
:::

جدول **`news`** أغنى جدول في الموقع. مقارنة بمصفوفة `$latest_news`:

| العمود | دوره |
|---|---|
| `title`، `slug` | العنوان، ونسخته اللاتينية للرابط (فريدة: السطر 189) |
| `summary`، `content` | **جديد**: الملخص (يظهر في قوائم الأخبار) والمحتوى الكامل. المحتوى من نوع `MEDIUMTEXT` (حتى 16 ميغابايت بدل 64 كيلوبايت للنوع `TEXT`)، لأنه نص **منسّق** (عناوين، جداول، صور...) يكتبه المدير بمحرر النصوص في الفصل 41 |
| `title_fr` ... `content_en` | ترجمات العنوان والملخص والمحتوى |
| `main_image` | الصورة الرئيسية (اختيارية: `NULL`) |
| `author_id` | **جديد**: كاتب الخبر، رقم حسابه في `users` |
| `published_date` | تاريخ النشر |
| `status` | **جديد**: الحالة: `draft` مسودة، `published` منشور، `archived` مؤرشف. الصفحة لا تعرض إلا المنشور |
| `views_count` | عدد المشاهدات |
| `is_featured` | **جديد**: خبر مميز |
| `show_in_ticker` | يظهر في الشريط المتحرك |
| `order`، `created_at`، `updated_at` | الترتيب، وتاريخا الإنشاء وآخر تعديل |

- **السطر 190**: **فهرس** مركّب على عمودين `(status, published_date)`، لأن أكثر استعلام سنكتبه هو «الأخبار المنشورة مرتبة بالتاريخ»، والفهرس يجعله سريعاً حتى مع آلاف الأخبار.
- **السطر 191**: **المفتاح الأجنبي** `fk_news_author`: `author_id` يجب أن يكون رقماً موجوداً في `users.id`، و`ON DELETE SET NULL`: إن حُذف حساب الكاتب يبقى الخبر بلا كاتب. (هذا سبب كتابة جدول `users` أولاً.)
- **السطر 192** `ROW_FORMAT=DYNAMIC`: صيغة تخزين تسمح بفهرس فريد على `VARCHAR(300)` بترميز utf8mb4، فالصيغ القديمة لا تقبل فهارس أطول من 767 بايت.

### النشاطات

@file database/schema.sql 221-255

(بين الأخبار والنشاطات في الملف النهائي جدولا صور الأخبار و«آخر المستجدات»: الفصل 29.)

مقارنة بمصفوفة `$featured_activities`: نفس المفاتيح، وجديد: `description` (الوصف الكامل)، و`organizer` (المنظّم)، و`is_featured` (يظهر في الصفحة الرئيسية)، و`is_active`، و`views_count`، و`order`. ونوع النشاط `activity_type` (السطر 230) يخزّن الرمز اللاتيني القصير بقيمة افتراضية `culture`، والتعليق يذكّر بالرموز الممكنة: `sport | culture | scientific | social | artistic | other`. والسطر 254 فهرس لاستعلام «النشاطات المفعّلة مرتبة بالتاريخ».

::: why
لماذا نخزّن `sport` بدل «رياضي»؟ لأن الرمز ثابت لا يتغير، بينما قد نغيّر التسمية المعروضة يوماً («رياضة» بدل «رياضي») دون أن نحتاج تعديل آلاف الصفوف. كما أن المقارنة بالرموز في الكود أسهل وأقل عرضة لأخطاء الإملاء. هذا ما فعلناه بالمصفوفة `$activity_types` في الفصل 11.
:::

## استيراد الملف

1. في phpMyAdmin اختر قاعدة البيانات `dou_setif` من القائمة اليسرى.
2. اضغط تبويب **Import** (استيراد).
3. **Choose File** ← اختر `C:\xampp\htdocs\dou-setif\database\schema.sql` ← اضغط **Import** (أو Go) أسفل الصفحة.
4. تظهر رسالة خضراء، وتظهر في القائمة اليسرى سبعة جداول: `activities`، `cites`، `departements`، `news`، `sliders`، `statistics`، `users`.

## التحقق

في تبويب **SQL** لقاعدة البيانات `dou_setif` نفّذ هذه الاستعلامات واحداً واحداً، ولاحظ أنها **نفس منطق** مصفوفاتنا وحلقاتنا:

```sql مثال
SELECT * FROM sliders WHERE is_active = 1 ORDER BY `order`;
SELECT title, published_date FROM news WHERE status = 'published' ORDER BY published_date DESC LIMIT 5;
SELECT title FROM news WHERE show_in_ticker = 1 ORDER BY `order`;
SELECT name FROM departements WHERE is_active = 1 ORDER BY `order`;
SELECT COUNT(*) FROM cites WHERE is_active = 1;
```

إن ظهرت النتائج والعناوين العربية سليمة فقاعدة البيانات جاهزة. في الفصل القادم نجعل `index.php` ينفّذ هذه الاستعلامات بنفسه بدل المصفوفات.

::: try
في phpMyAdmin افتح الجدول `cites` ← **Browse**، وانقر مرتين على اسم إقامة لتعديله مباشرة، ثم أرجعه. وجرّب تبويب **Insert** لإضافة إقامة ثامنة تجريبية، ثم احذفها (أيقونة **Delete** في صفها).
:::
