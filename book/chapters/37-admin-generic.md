## الفكرة: إعدادات بدل كود

ارجع إلى `admin_news_form()` في الفصل 36، واسأل: ما الذي يخص الأخبار فيها حقاً؟ أسماء الحقول (`title`، `content`...)، وأيها مطلوب، وأن `status` قائمة خيارات، وأن `published_date` تاريخ ووقت، وأن الصورة تُرفع إلى `news/main`. أما الباقي (قراءة الحقل، ورسالة «هذا الحقل مطلوب.»، وتحويل التاريخ، والتحقق من الصورة ورفعها، وحذف القديمة، ورسالة النجاح) فهو نفسه في كل جدول. فلنكتب ما يخص الجدول **وصفاً**:

```php وصف جدول السلايدر (مبسّط)
'sliders' => [
    'model'  => Slider::class,                  // النموذج (الفصل 22)
    'plural' => 'السلايدر',                      // عنوان القسم
    'list'   => ['image', 'title', 'is_active'], // أعمدة القائمة
    'fields' => [                                // حقول نموذج الإضافة والتعديل
        'title'     => ['type' => 'text', 'label' => 'العنوان'],
        'image'     => ['type' => 'image', 'label' => 'الصورة', 'dir' => 'slider'],
        'is_active' => ['type' => 'bool', 'label' => 'نشط'],
    ],
],
```

ويقرأ المحرك هذا الوصف فيعرف: في القائمة صورة مصغّرة وعنوان وعلامة صح أو خطأ، وفي النموذج حقل نص وحقل رفع صورة ومربع اختيار، وعند الحفظ يتحقق من الصورة ويرفعها إلى `uploads/slider/`. إضافة جدول جديد إلى اللوحة تعني إضافة وصف، لا كتابة صفحات. و`Slider::class` تعطي اسم الصنف نصاً (`'Slider'`)، فيستدعي المحرك به دوال النموذج.

الروابط لا تتغير: `{model}` في `/admin/{model}/` (الفصل 36) يصبح أي مفتاح من مفاتيح الإعدادات.

## ملف الإعدادات

### مفاتيح القسم وأنواع الحقول

قبل الملف، هذان جدولان ترجع إليهما كلما احتجت. أولاً مفاتيح وصف القسم:

| المفتاح | معناه |
|---|---|
| `model` | صنف النموذج |
| `group` و `icon` | مجموعته في القائمة الجانبية، وأيقونته |
| `label` و `plural` | اسم السجل الواحد («خبر») واسم القسم («الأخبار») |
| `list` | أعمدة جدول القائمة |
| `links` | الأعمدة التي تفتح صفحة التعديل عند النقر |
| `editable` | أعمدة تُعدَّل مباشرة من القائمة |
| `filters` | الفلاتر الجانبية |
| `search` | أعمدة البحث |
| `order_by` و `per_page` | الترتيب، وعدد السجلات في الصفحة |
| `actions` | إجراءات جماعية (نشر، تمييز...) |
| `fields` | حقول نموذج الإضافة والتعديل |
| `inlines` | صور أو وثائق مرتبطة تُدار داخل صفحة السجل |
| `columns` | أعمدة محسوبة ليست في الجدول |
| `badge` | عدد أحمر بجانب القسم في القائمة الجانبية |
| `view_url` | زر «عرض في الموقع» |
| `on_view` و `on_save` | دالة تُنفَّذ عند فتح سجل، وأخرى بعد حفظه |
| `can_add` و `can_edit` و `can_delete` | منع الإضافة أو التعديل أو الحذف |
| `hidden` | لا يظهر في القائمة الجانبية |
| `superuser_only` | للمدير العام فقط |

وثانياً أنواع الحقول، وما يصنعه المحرك لكل نوع:

| النوع | حقل الإدخال | التحقق والحفظ |
|---|---|---|
| `text` و `textarea` | سطر نصي، أو مربع نص متعدد الأسطر | الطول الأقصى `max` |
| `email` و `url` | بريد أو رابط (من اليسار لليمين) | صيغة صحيحة |
| `int` و `decimal` | رقم صحيح، أو رقم بمنزلتين | رقم، وحدود `min` |
| `bool` | مربع اختيار | 1 أو 0 |
| `select` | قائمة من خيارات النموذج (`$choices`، الفصل 21) | القيمة من الخيارات فقط |
| `fk` | قائمة بسجلات جدول آخر | السجل موجود فعلاً |
| `date` و `datetime` | منتقي تاريخ، أو تاريخ ووقت | تاريخ صالح |
| `image` و `file` | رفع ملف مع معاينة الحالي | الصنف `Upload` (الفصل 30) |
| `slug` | رابط يُملأ تلقائياً من العنوان | حروف وأرقام وشرطات |
| `color` و `icon` | منتقي لون، واسم أيقونة مع معاينتها | صيغة اللون |
| `password` | كلمة مرور (فارغة = بلا تغيير) | قواعد القوة، ثم التشفير |
| `readonly` | نص للعرض فقط | لا يُقرأ من النموذج أبداً |

انتهى دور الملفات المؤقتة. تأكد أنك حذفت `news_list.php` و`news_form.php` من `app/views/admin/`، ثم احذف المجلد `admin-demo/` كله من جذر المشروع: صفحاته الثلاث صارت `index.php` و`list.php` و`form.php`، و`admin.css` و`admin.js` في `assets/` منذ البداية.

يجب أن يكون في `app/views/admin/` الآن ستة ملفات بالضبط:

```text محتوى app/views/admin/
delete.php  form.php  index.php  layout.php  list.php  password.php
```

## التجربة

1. افتح `http://localhost/dou-setif/admin/`: الصفحة الرئيسية الحقيقية بالبطاقات وكل الأقسام، والقائمة الجانبية مجمّعة.
2. **شريحة جديدة** (وعد الفصل 25): «السلايدر» ← «إضافة صورة سلايدر»، واكتب عنواناً واختر صورة، ثم «حفظ». افتح الصفحة الرئيسية: الشريحة في السلايدر.
3. جرّب رفع ملف `.php` أو ملف نصي غيّرت امتداده إلى `.jpg` صورةً للشريحة: يرفضه `Upload` برسالة خطأ.
4. **ملف للتحميل**: «مركز التحميلات» ← «إضافة ملف»، وارفع PDF. في `/downloads/` اضغط «تحميل»: يبدأ التحميل ويزيد العداد في القائمة.
5. **كلمة مرور طالب** (وعد الفصل 31): «المستخدمون» ← اسم مستخدم الطالب (رقم تسجيله)، واكتب كلمة مرور جديدة واحفظ. يدخل الطالب بها، وتخرج جلساته القديمة.
6. «طلبات الطلاب» ← طلب معلق، وغيّر الحالة إلى «معتمد» واحفظ: يصل الطالب إشعار، ويُسجَّل اسمك مراجِعاً.
7. «رسائل اتصل بنا»: افتح رسالة جديدة، ثم ارجع: نقص العدد الأحمر بجانب القسم.
8. في «الأخبار»: صفِّ بـ «خبر مميز: نعم»، ثم ابحث بكلمة، ولاحظ الرابط: `?f_is_featured=1&q=...`. حدّد خبرين واختر «تحويل إلى مسودة».
9. افتح خبراً وأضف إلى معرضه صورتين دفعة واحدة، ثم احذف الخبر: اختفت صورته وصور معرضه من `uploads/`.
10. أنشئ مستخدماً موظفاً (بلا «مدير عام») وادخل به: لا يرى «المستخدمون»، و`/admin/users/` تعطيه 404.

::: try تمارين
1. أضف إلى «الأسئلة الشائعة» إجراءً جماعياً «إخفاء الأسئلة المحددة» يضع `is_active = 0`. (سطر واحد في `actions`.)
2. أضف عموداً محسوباً في قائمة «الإقامات الجامعية» يعرض عدد صور كل إقامة، على مثال `faq_count`.
3. اجعل `per_page` لقسم «زيارات الموقع» 100، وجرّب الترقيم.
:::

::: summary
- لوحة الإدارة **محرك عام** يقرأ وصف كل جدول من `admin_config.php`: أربع دوال (قائمة، إضافة، تعديل، حذف) تخدم 26 قسماً، بدل دوال لكل جدول كما في الفصل 36.
- الوصف يحدد الأعمدة والروابط والتعديل المباشر والفلاتر والبحث والإجراءات والحقول والملفات المرتبطة، والخطافات `on_view` و`on_save`.
- الأمان: الأسماء من الإعدادات لا من الرابط، والقيم معاملات، والحقول المعروضة فقط لا تُقرأ، والخيارات تُتحقق، والملفات يفحصها `Upload`، والحذف بـ POST فقط.
- الملفات: نحذف المرفوع للتو إن فشل الحفظ، والمستبدَل بعد النجاح، ولا نحذف ملفاً يستعمله سجل آخر.
- خدعة الحقل المخفي قبل المربع لمعرفة «ألغى التحديد»، و`$_FILES` لعدة ملفات قوائم خصائص لا قائمة ملفات.
- حذفنا `news_list.php` و`news_form.php` و`admin-demo/`: اللوحة الآن مطابقة للمشروع النهائي.
:::
