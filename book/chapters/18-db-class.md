# الاتصال بقاعدة البيانات: الصنف DB

::: intro
في الفصل 15 كتبنا في أعلى الصفحة الرئيسية كود الاتصال بقاعدة البيانات (`new PDO(...)` بإعداداته) ثم الاستعلامات. كل صفحة في الموقع تحتاج ذلك. بدل أن نكرر كود PDO في كل مكان، نكتب **صنفاً** صغيراً اسمه `DB` يقدّم دوالاً قصيرة وواضحة مثل `DB::all()` و`DB::insert()`، ويستعمل الاستعلامات المحضّرة تلقائياً فيحمينا من حقن SQL دون أن نفكر في ذلك. وهو أول صنف نكتبه، فنبدأ بفهم الأصناف.
:::

## الأصناف والكائنات باختصار

في الفصل 15 استعملنا الصنف الجاهز `PDO`: `$pdo = new PDO(...)` ثم `$pdo->query(...)`. الآن سنكتب أصنافنا. **الصنف** (class) قالب يصف نوعاً من الأشياء: بياناته (**خصائص**) وما يستطيع فعله (**دوال**، وتسمّى في الأصناف methods). و**الكائن** (object) نسخة حقيقية من هذا القالب.

```php مثال
<?php
class Student
{
    public string $name;               // خاصية عامة
    private string $password = '';     // خاصية خاصة: لا تُقرأ من خارج الصنف
    public static int $count = 0;      // خاصية «ثابتة» مشتركة بين كل الكائنات

    public function __construct(string $name)   // تُنفَّذ تلقائياً عند new
    {
        $this->name = $name;           // $this = الكائن الحالي
        self::$count++;
    }

    public function greet(): string
    {
        return 'مرحباً ' . $this->name;
    }

    public static function total(): int          // دالة ثابتة: تُستدعى بلا كائن
    {
        return self::$count;
    }
}

$s = new Student('أحمد');      // إنشاء كائن
echo $s->greet();              // استدعاء دالة بالسهم ->
echo $s->name;
echo Student::total();         // دالة ثابتة بالعامل ::
```

| الكلمة | معناها |
|---|---|
| `public` / `protected` / `private` | متاح للجميع / للصنف وأبنائه / للصنف وحده |
| `static` | ينتمي للصنف نفسه لا لكائن بعينه، ويُستدعى بـ `::` |
| `self::` | الصنف الذي كُتب فيه الكود |
| `final` | لا يمكن وراثة الصنف (سنرى الوراثة في الفصل 21) |

الصنف `DB` الذي سنكتبه كله دوال **ثابتة** (static): لا نحتاج إنشاء كائن منه، بل نستدعي دواله باسمه مباشرة `DB::all(...)`، كما نستدعي دالة عادية لكن مجمّعة تحت اسم واحد.

## ما الذي نريده؟

نريد أن نكتب في أي مكان من الموقع أسطراً مثل هذه:

```php مثال
$all   = DB::all('SELECT * FROM news WHERE status = ?', ['published']);   // كل الصفوف
$one   = DB::one('SELECT * FROM news WHERE id = ?', [5]);                // صف واحد أو null
$count = DB::value('SELECT COUNT(*) FROM news');                         // قيمة واحدة
$id    = DB::insert('contact_messages', ['full_name' => 'أحمد', 'email' => 'a@b.dz']);
DB::update('news', ['views_count' => 10], 'id = :id', ['id' => 5]);
DB::delete('news_images', 'id = ?', [12]);
```

كلها دوال **ثابتة** (static) نستدعيها باسم الصنف مباشرة `DB::` دون إنشاء كائن.

## الاتصال: الدالة pdo()

افتح `app/core/DB.php` (أنشأناه فارغاً) واكتب:

@file app/core/DB.php 1-34

- **السطر 6** `final class DB`: صنف لا يُورَث.
- **السطر 8**: خاصية ثابتة خاصة تحمل كائن الاتصال، وقيمتها `null` في البداية. النوع `?PDO` يعني «كائن PDO أو null».
- **السطر 12**: إن لم يكن الاتصال موجوداً ننشئه، وإن كان موجوداً نُرجعه مباشرة (السطر 33). هكذا يُفتح **اتصال واحد فقط** في كل طلب مهما كان عدد الاستعلامات، ولا يُفتح أصلاً في الصفحات التي لا تحتاج قاعدة البيانات. يسمّى هذا «الإنشاء الكسول» (lazy).
- **السطر 13**: نقرأ إعدادات `db` من `config.php` بالدالة `config()` (الفصل 16)، بدل `$config = require 'config.php'` في الفصل 15.
- **السطران 14–15**: `sprintf` تبني نص الاتصال (DSN) بوضع القيم مكان كل `%s` بالترتيب، فينتج: `mysql:host=127.0.0.1;port=3306;dbname=dou_setif;charset=utf8mb4`، نفس النص الذي بنيناه بالأقواس المعقوفة في الفصل 15.
- **الأسطر 17–22**: خيارات PDO:
  - `ERRMODE_EXCEPTION` و`FETCH_ASSOC`: الخياران اللذان استعملناهما في الفصل 15.
  - `EMULATE_PREPARES => true`: يحضّر PDO الاستعلام بنفسه في PHP بدل إرساله على مرحلتين إلى MySQL. أسرع (رحلة واحدة إلى الخادم بدل اثنتين)، ويسمح بتكرار الاسم نفسه `:id` أكثر من مرة في استعلام واحد. والأمان نفسه، لأن PDO يهرّب كل قيمة بالطريقة الصحيحة حسب ترميز الاتصال.
  - `STRINGIFY_FETCHES => false`: لا تحوّل الأرقام إلى نصوص قدر الإمكان.
- **الأسطر 23–28**: إن فشل الاتصال نلتقط الخطأ ونرمي رسالة عربية واضحة. لاحظ أننا **لا نضع** رسالة PDO الأصلية لأنها قد تحتوي اسم المستخدم أو تفاصيل الخادم؛ نكتفي برمز الخطأ.
- **السطر 31**: نضبط المنطقة الزمنية لاتصال MySQL على +01:00، فتتطابق التواريخ التي ينتجها MySQL (`CURRENT_TIMESTAMP`) مع التي ينتجها PHP.

## قلب الصنف: الدالة query()

@file app/core/DB.php 35-57

هذه الدالة تستعملها كل الدوال الأخرى. تأخذ نص الاستعلام ومصفوفة القيم:

- **السطر 39**: `prepare` تحضّر الاستعلام بعلاماته `?` أو `:name`.
- **الأسطر 40–54**: نربط كل قيمة بمكانها بالدالة `bindValue` مع تحديد **نوعها**:
  - **السطر 41**: إن كان مفتاح القيمة رقماً (مصفوفة مرقّمة `[5, 'abc']`) فهي لعلامة `?`، والعلامات في PDO تبدأ من 1، لذا نضيف 1 للمفتاح. وإن كان المفتاح نصاً (`['id' => 5]`) فهو اسم، ونضيف له النقطتين `:` إن لم تكن موجودة.
  - **الأسطر 42–52**: العدد الصحيح يُربط كعدد `PARAM_INT`، والقيمة المنطقية تتحول إلى 1 أو 0، و`null` تُربط كـ `NULL` حقيقية، وكل ما عدا ذلك نص.
- **السطر 55**: التنفيذ، ثم نُرجع «العبارة» (statement) لتقرأ منها الدوال الأخرى النتائج.

::: why
لماذا نهتم بنوع القيمة؟ خذ هذا الاستعلام: `SELECT * FROM news LIMIT ?` مع القيمة `6`. لو رُبطت كنص لأصبح الاستعلام `LIMIT '6'`، وهذا خطأ في MySQL. بربطها كعدد صحيح يصبح `LIMIT 6`. ولهذا أيضاً سنحرص لاحقاً على تحويل الأرقام القادمة من الرابط إلى أعداد بـ `(int)`.
:::

## دوال القراءة

@file app/core/DB.php 58-77

ثلاث دوال قصيرة فوق `query()`:

| الدالة | تُرجع | مثال |
|---|---|---|
| `all()` | كل الصفوف كمصفوفة (فارغة إن لم توجد نتائج) | قائمة الأخبار |
| `one()` | أول صف، أو `null` إن لم يوجد | خبر برقمه |
| `value()` | قيمة العمود الأول من الصف الأول، أو `null` | `SELECT COUNT(*) ...` |

`fetch()` و`fetchColumn()` تُرجعان `false` عندما لا توجد نتيجة، فنحوّل `false` إلى `null` لأنها أوضح معنى.

## الإضافة والتعديل والحذف

@file app/core/DB.php 78-111

**`insert($table, $data)`** تبني جملة INSERT من مفاتيح المصفوفة. مثلاً:

```php مثال
DB::insert('faqs', ['question' => 'متى تبدأ التسجيلات؟', 'category_id' => 2]);
```

فتبني الجملة:

```sql مثال
INSERT INTO `faqs` (`question`, `category_id`) VALUES (:question, :category_id)
```

ثم تربط القيمة `'متى تبدأ التسجيلات؟'` بالعلامة `:question`، والقيمة `2` بالعلامة `:category_id`.

- **السطر 81**: `array_keys` تعطي أسماء الأعمدة.
- **السطر 83**: `array_map` مع دالة سهمية تحيط كل اسم بالعلامة `` ` ``.
- **السطر 84**: وتصنع لكل عمود علامة باسمه `:question`.
- **السطر 86**: تُرجع رقم `id` الجديد.

**`update($table, $data, $where, $whereParams)`**:

```php مثال
DB::update('news', ['views_count' => 151], '`id` = :id', ['id' => 7]);
// UPDATE `news` SET `views_count` = :set_views_count WHERE `id` = :id
```

- **الأسطر 96–99**: نسمّي علامات الأعمدة بالبادئة `set_`، حتى لا تتصادم مع أسماء الشرط (تخيّل تحديث العمود `id` بشرط على `id`!).
- **الأسطر 101–103**: ندمج قيم الشرط، ويجب أن تكون **مسمّاة** لأن PDO لا يقبل خلط `?` مع `:name` في الاستعلام نفسه.
- **السطر 105**: `rowCount()` عدد الصفوف التي تغيّرت.

**`delete($table, $where, $params)`** تحذف الصفوف المطابقة للشرط وتُرجع عددها.

::: warning
أسماء الجداول والأعمدة وجزء الشرط `$where` تُكتب **مباشرة** في نص الاستعلام، فيجب أن تأتي من كودنا نحن فقط، وليس من الزائر أبداً. أما **القيم** فتمرّ دائماً عبر المصفوفة فتُربط بأمان.
:::

## المعاملات ودالتان صغيرتان

@file app/core/DB.php 112-138

**`transaction($fn)`**: أحياناً نريد تنفيذ عدة عمليات **كلها أو لا شيء**. مثلاً عند تقديم طالب لطلب: نحفظ الطلب، ثم نحفظ وثائقه، ثم نرسل له إشعاراً. لو فشلت الخطوة الثانية لبقي طلب بلا وثائق. داخل «معاملة» (transaction) لا تُعتمد التغييرات إلا بعد نجاح الكل (`commit`)، وإن رمى أي جزء استثناء نتراجع عن كل شيء (`rollBack`) ثم نعيد رمي الاستثناء.

```php مثال
DB::transaction(function () use ($data) {
    $appId = DB::insert('student_applications', $data);
    DB::insert('application_documents', ['application_id' => $appId, /* ... */]);
});
```

`callable` نوع يعني «شيء يمكن استدعاؤه»: دالة مجهولة أو اسم دالة.

**`in($values)`** تصنع علامات استفهام بعدد القيم، لاستعمالها مع `IN`:

```php مثال
$ids = [3, 7, 9];
DB::all('SELECT * FROM news WHERE id IN (' . DB::in($ids) . ')', $ids);
// SELECT * FROM news WHERE id IN (?, ?, ?)
```

وإن كانت المصفوفة فارغة تُرجع `NULL` فيصبح الشرط `IN (NULL)` الذي لا يطابق أي صف، بدل `IN ()` الذي هو خطأ في SQL.

**`like($term)`** تجهّز كلمة بحث لاستعمالها مع `LIKE`: تضع `%` حولها، وتهرّب الرموز `%` و`_` التي لها معنى خاص في `LIKE`، فإن بحث الزائر عن `100%` لا يُفهم الرمز كـ «أي أحرف».

## مقارنة مع الفصل 15

| الفصل 15 (في الصفحة نفسها) | الآن (من أي مكان في الموقع) |
|---|---|
| `$config = require ...; $pdo = new PDO(...)` في كل صفحة | اتصال واحد تلقائي عند أول استعلام |
| `$pdo->query("SELECT ...")->fetchAll()` | `DB::all('SELECT ...')` |
| `$pdo->query("SELECT COUNT(*) ...")->fetchColumn()` | `DB::value('SELECT COUNT(*) ...')` |
| `prepare()` ثم `execute()` يدوياً عند وجود قيم | `DB::all('... WHERE slug = ?', [$slug])` دائماً محضّر |

## اختبار الاتصال

أضف إلى الملف المؤقت `hello.php` (من الفصل السابق) هذا الجزء قبل `</body>`:

```php hello.php (ملف مؤقت، أضف قبل </body>)
    <h3>من قاعدة البيانات</h3>
    <?php
    $count = DB::value('SELECT COUNT(*) FROM news');
    $rows  = DB::all('SELECT title FROM news WHERE status = ? ORDER BY published_date DESC LIMIT ?', ['published', 3]);
    $first = DB::one('SELECT * FROM departements ORDER BY `order` LIMIT 1');
    ?>
    <p>عدد الأخبار: <?= $count ?></p>
    <ul>
        <?php foreach ($rows as $row): ?>
            <li><?= e($row['title']) ?></li>
        <?php endforeach; ?>
    </ul>
    <p>أول مصلحة: <?= e($first['name'] ?? '—') ?></p>
```

حدّث `http://localhost/dou-setif/hello.php`. يجب أن ترى عدد الأخبار (5) وعناوين آخر ثلاثة أخبار واسم أول مصلحة («مصلحة المنح»)، من البيانات التجريبية التي أدخلناها في الفصل 14. لاحظ `LIMIT ?` مع القيمة `3`: الصنف ربطها كعدد صحيح فصار الاستعلام `LIMIT 3` (السطران 42–43). إن ظهرت صفحة خطأ فاقرأ رسالتها وراجع جدول رموز الأخطاء أعلاه.

::: summary
- الصنف `DB` يفتح اتصالاً واحداً عند أول حاجة إليه.
- `query()` تربط كل قيمة بنوعها الصحيح عبر استعلامات مُحضَّرة.
- `all()` و`one()` و`value()` للقراءة، و`insert()` و`update()` و`delete()` للكتابة.
- `transaction()` لتنفيذ عدة عمليات كوحدة واحدة.
- القيم تمر دائماً كمعاملات، أما أسماء الجداول والأعمدة فمن كودنا فقط.
:::
