# لوحة الإدارة العامة: كل الجداول بمحرك واحد

::: intro
في الفصل 39 أدرنا الأخبار بدوال كتبناها بأيدينا، ثم أضفنا إليها الترجمة (الفصل 40) والمحرر (الفصل 41). جدول واحد احتاج نحو 350 سطراً بين المتحكم والقوالب. في هذا الفصل نعمّم ما فعلناه: **نصف كل جدول في مصفوفة إعدادات**، ثم نكتب **محركاً واحداً** يقرأ الوصف ويبني منه الصفحات، بحقول الفرنسية والإنجليزية وزر الترجمة ومحرر النصوص في كل قسم. النتيجة: 26 قسماً (السلايدر، والأخبار، والطلبة، والمستخدمون...) تخدمها أربع صفحات فقط: القائمة، والإضافة، والتعديل، والحذف. وفي آخر الفصل نحذف الملفات المؤقتة ومجلد `admin-demo/`، فتكتمل اللوحة كما هي في المشروع النهائي، إلا مسابقات التوظيف: قسمها نضيفه في الفصل 44، وصفحات دراسة ملفات المترشحين في الفصل 48.

## خريطة الفصل

الروابط سجّلناها في `app/routes.php` في الفصل 20، واستعملنا بعضها للأخبار وحدها منذ الفصل 39:

| الصفحة | الرابط | الدالة |
|---|---|---|
| رئيسية اللوحة | `/admin/` | `admin_index` |

## الفكرة: إعدادات بدل كود

ارجع إلى `admin_news_form()` في الفصول 39–41، واسأل: ما الذي يخص الأخبار فيها حقاً؟ أسماء الحقول (`title`، `content`...)، وأيها مطلوب، وأن `status` قائمة خيارات، وأن `published_date` تاريخ ووقت، وأن المحتوى نص منسّق، وأن الصورة تُرفع إلى `news/main`. أما الباقي (قراءة الحقل، ورسالة «هذا الحقل مطلوب.»، وتحويل التاريخ، والتحقق من الصورة ورفعها، وحذف القديمة، وحقول الترجمة، ورسالة النجاح) فهو نفسه في كل جدول. فلنكتب ما يخص الجدول **وصفاً**:

```php وصف جدول السلايدر (مبسّط)
'sliders' => [
    'model'  => Slider::class,                  // النموذج (الفصل 23)
    'plural' => 'السلايدر',                      // عنوان القسم
    'list'   => ['image', 'title', 'is_active'], // أعمدة القائمة
    'fields' => [                                // حقول نموذج الإضافة والتعديل
        'title'     => ['type' => 'text', 'label' => 'العنوان'],
        'image'     => ['type' => 'image', 'label' => 'الصورة', 'dir' => 'slider'],
        'is_active' => ['type' => 'bool', 'label' => 'نشط'],
    ],
],
```

ويقرأ المحرك هذا الوصف فيعرف: في القائمة صورة مصغّرة وعنوان وعلامة صح أو خطأ، وفي النموذج حقل نص وحقل رفع صورة ومربع اختيار، وعند الحفظ يتحقق من الصورة ويرفعها إلى `uploads/slider/`. وحقول الترجمة يعرفها وحده من `$translatable` في النموذج (الفصل 22): `title` مترجم في `Slider`، فتحته حقلا `FR` و`EN`. إضافة جدول جديد إلى اللوحة تعني إضافة وصف، لا كتابة صفحات.

هذا بالضبط ما بدأناه في الفصل 40 بالدالة المؤقتة `admin_resources()`: وصف لقسم الأخبار وحده، بحقوله المترجمة فقط. الآن يصير لكل قسم وصف كامل.

## ملف الإعدادات

### مفاتيح القسم وأنواع الحقول

قبل الملف، هذان جدولان ترجع إليهما كلما احتجت. أولاً مفاتيح وصف القسم:

| المفتاح | معناه |
|---|---|
| `model` | صنف النموذج |
| `group` و`icon` | مجموعته في القائمة الجانبية، وأيقونته |
| `label` و`plural` | اسم السجل الواحد («خبر») واسم القسم («الأخبار») |
| `list` | أعمدة جدول القائمة |
| `links` | الأعمدة التي تفتح صفحة التعديل عند النقر |
| `editable` | أعمدة تُعدَّل مباشرة من القائمة |
| `filters` | الفلاتر الجانبية |
| `search` | أعمدة البحث |
| `order_by` و`per_page` | الترتيب، وعدد السجلات في الصفحة |
| `actions` | إجراءات جماعية (نشر، تمييز...) |
| `fields` | حقول نموذج الإضافة والتعديل |
| `inlines` | صور أو وثائق مرتبطة تُدار داخل صفحة السجل |
| `columns` | أعمدة محسوبة ليست في الجدول |
| `badge` | عدد أحمر بجانب القسم في القائمة الجانبية |
| `view_url` | زر «عرض في الموقع» |
| `on_view` و`on_save` | دالة تُنفَّذ عند فتح سجل، وأخرى بعد حفظه |
| `can_add` و`can_edit` و`can_delete` | منع الإضافة أو التعديل أو الحذف |
| `hidden` | لا يظهر في القائمة الجانبية |
| `superuser_only` | للمدير العام فقط |
| `permission` و`before_delete` | صلاحية إضافية للقسم، ودالة تمنع الحذف بسبب. نستعملهما في الفصل 44 |

وثانياً أنواع الحقول، وما يصنعه المحرك لكل نوع:

| النوع | حقل الإدخال | التحقق والحفظ |
|---|---|---|
| `text` و`textarea` | سطر نصي، أو مربع نص متعدد الأسطر | الطول الأقصى `max` |
| `richtext` | محرر TinyMCE (الفصل 41) | التنظيف بـ `RichText::normalize()`، والطول على النص بلا وسوم |
| `email` و`url` | بريد أو رابط كامل (من اليسار لليمين) | صيغة صحيحة، والرابط `http(s)` فقط |
| `link` | رابط داخلي (`/news/`) أو كامل | `is_allowed_link()` (الفصل 17) |
| `int` و`decimal` | رقم صحيح، أو رقم بمنزلتين | رقم، وحدود `min` و`max_value` |
| `bool` | مربع اختيار | 1 أو 0 |
| `select` | قائمة من خيارات النموذج (`$choices`، الفصل 22) | القيمة من الخيارات فقط |
| `fk` | قائمة بسجلات جدول آخر | السجل موجود فعلاً |
| `date` و`datetime` | منتقي تاريخ، أو تاريخ ووقت | تاريخ صالح |
| `image` و`file` | رفع ملف مع معاينة الحالي | الصنف `Upload` (الفصل 32) |
| `slug` | رابط يُملأ تلقائياً من العنوان | حروف وأرقام وشرطات |
| `color` و`icon` | منتقي لون، واسم أيقونة مع معاينتها | صيغة اللون |
| `password` | كلمة مرور (فارغة = بلا تغيير) | قواعد القوة، ثم التشفير |
| `readonly` | نص للعرض فقط | لا يُقرأ من النموذج أبداً |

## المحرك: admin.php من جديد

نعيد كتابة `app/controllers/admin.php`. يبقى فيه كل ما كتبناه نهائياً في الفصول 36–41: رأس الملف، والحارس `admin_guard()` و`admin_render()`، والدخول والخروج، وكلمة المرور والاستعادة، ودوال الترجمة وزرها، ورفع الصور، وترجمة المحتوى، والبحث عن TinyMCE. ونستبدل ما كان مؤقتاً:

1. `admin_resources()` المؤقتة (بعد تعليق رأس الملف).

ونضيف دوال جديدة بعد دوال الترجمة، وفي آخر الملف. صناديق هذا الفصل بأرقام أسطر الملف النهائي، وفيه سطور المسابقات التي نضيفها في الفصل 48، فتختلف أرقام ملفك قليلاً بعد أول شريط مخطّط (كما في `config.php`، الفصل 15). المهم أن يكون المحتوى نفسه، وبالترتيب نفسه.

3. جرّب رفع ملف `.php` أو ملف نصي غيّرت امتداده إلى `.jpg` صورةً للشريحة: يرفضه `Upload` برسالة خطأ.

7. «رسائل اتصل بنا»: افتح رسالة جديدة، ثم ارجع: نقص العدد الأحمر بجانب القسم.
