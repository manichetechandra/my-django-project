# القوالب: فصل الكود عن التصميم

::: intro
كل صفحات الموقع تتشارك الرأس نفسه (الشعار وشريط التنقل) والتذييل نفسه، ويختلف الوسط فقط. لن ننسخ الرأس والتذييل في 60 صفحة! سنكتب محرك قوالب صغيراً (أقل من 100 سطر) يسمح لكل صفحة بأن **ترث** قالباً أساسياً وتملأ «فراغاته» فقط. ثم نكتب صفحات الأخطاء (404، 403، 500...).
:::

## ما هو القالب؟

**القالب** (template أو view) ملف PHP أغلبه HTML، فيه مواضع صغيرة لطباعة القيم. منطق الصفحة (قراءة قاعدة البيانات، التحقق من النماذج) يكون في **المتحكم**، والقالب يعرض فقط ما يُعطى له:

```php المتحكم: يجهّز البيانات
function news_list(): void
{
    $news = DB::all('SELECT * FROM news WHERE status = ?', ['published']);
    render('news/news_list', ['news_list' => $news]);   // يرسلها إلى القالب
}
```

```php القالب app/views/news/news_list.php: يعرضها
<?php foreach ($news_list as $item): ?>
    <h3><?= e($item['title']) ?></h3>
<?php endforeach; ?>
```

في القوالب نستعمل دائماً الصيغة البديلة لـ PHP التي رأيناها في الفصل 3 (`if (): ... endif;` و`foreach (): ... endforeach;`) و`<?= e(...) ?>` للطباعة، فتبقى القوالب مقروءة وسط HTML.

## الوراثة: قالب أساسي وفراغات

الفكرة مأخوذة من أُطر عمل مشهورة: القالب الأساسي يحدد **كتلاً** (blocks) لها أسماء ومحتوى افتراضي، والصفحة تعلن أنها **ترث** القالب الأساسي وتعطي محتوى جديداً للكتل التي تريدها فقط.

<div class="flow">
  <div class="st"><b>news_list.php</b>extend + كتلة content</div><span class="ar">←</span>
  <div class="st hl"><b>View::render</b>يجمع الكتل</div><span class="ar">←</span>
  <div class="st"><b>base/base.php</b>الرأس + الكتل + التذييل</div><span class="ar">←</span>
  <div class="st"><b>HTML كامل</b>إلى المتصفح</div>
</div>

صفحة فرعية تبدو هكذا:

```php
<?php extend('base/base'); ?>

<?php block('title'); ?>الأخبار<?php endblock(); ?>

<?php block('content'); ?>
    <h1>آخر الأخبار</h1>
    ...
<?php endblock(); ?>
```

والقالب الأساسي `base/base.php` يحتوي في المكان المناسب:

```php
<title><?php block('title'); ?>مديرية الخدمات الجامعية<?php endblock(); ?></title>
...
<?php block('content'); ?><?php endblock(); ?>
```

## الصنف View

افتح `app/core/View.php`:

@file app/core/View.php 1-38

**الخصائص (الأسطر 13–16)** تحفظ حالة العرض الجاري:

- `$layout`: اسم القالب الذي أعلنت الصفحة الحالية أنها ترثه، أو `null`.
- `$blocks`: محتوى الكتل التي عرّفتها الصفحة الفرعية، مثل `['title' => 'الأخبار', 'content' => '<h1>...']`.
- `$stack`: أسماء الكتل المفتوحة حالياً (لأن الكتل قد تتداخل).
- `$inLayout`: هل نحن الآن داخل القالب الأساسي أم داخل الصفحة الفرعية؟

**الدالة `render($view, $context)`**:

1. **السطر 20**: نحفظ الحالة السابقة، ونعيدها في `finally` (السطر 36) مهما حدث. هذا يسمح باستدعاء `render()` من داخل `render()` (مثلاً عرض صفحة خطأ أثناء عرض صفحة أخرى) دون أن تختلط الكتل.
2. **السطر 26**: نعرض ملف الصفحة نفسها. أثناء ذلك تستدعي `extend()` فيُحفظ اسم القالب الأساسي، وتُحفظ كل كتلة في `$blocks`.
3. **الأسطر 28–33**: ما دام هناك قالب أساسي معلن، نعرضه. وإن كان هو أيضاً يرث قالباً آخر، تستمر الحلقة (سلسلة وراثة بأي طول).
4. **السطر 34**: نُرجع HTML آخر قالب عُرض، أي القالب الأساسي الذي وُضعت فيه الكتل.

::: note
لاحظ أن ناتج الصفحة الفرعية نفسه (السطر 26) يُستبدل في الحلقة بناتج القالب الأساسي. لذلك **كل ما تكتبه في صفحة فرعية خارج الكتل يُهمَل**. ضع كل شيء داخل `block()` و`endblock()`.
:::

@file app/core/View.php 40-57

**الدالة `renderFile()`** تعرض ملفاً واحداً وتُرجع ناتجه نصاً بدل طباعته:

- **السطر 45** `extract($__context, EXTR_SKIP)`: تحوّل كل مفتاح في المصفوفة إلى متغير. فإن كان السياق `['news_list' => [...], 'page_title' => 'الأخبار']` يصبح في القالب متغيران `$news_list` و`$page_title`. والخيار `EXTR_SKIP` يمنع الكتابة فوق متغير موجود، مثل `$__file` نفسه. ولهذا السبب بدأنا أسماء متغيرات الدالة بشرطتين `$__`: حتى لا تتصادم مع أسماء متغيرات القوالب.
- **السطور 47–56**: «التخزين المؤقت للمخرجات» (الفصل 3): `ob_start()` تبدأ الالتقاط، ثم `include` تنفّذ القالب فيذهب كل ما يطبعه إلى المخزن، ثم `ob_get_clean()` تُرجعه نصاً.
- **الأسطر 50–54**: إن حدث خطأ داخل القالب، نغلق كل المخازن التي فُتحت داخله قبل إعادة رمي الاستثناء، حتى لا يظهر نصف صفحة مع رسالة الخطأ.

@file app/core/View.php 59-76

الكتل نفسها تعمل بالالتقاط أيضاً:

- **`startBlock($name)`**: نضع اسم الكتلة في المكدس، ونبدأ التقاطاً جديداً.
- **`endBlock()`**: نُخرج اسم آخر كتلة مفتوحة، ونأخذ ما التُقط منذ بدايتها، ثم:
  - **داخل القالب الأساسي** (أو في قالب لا يرث شيئاً): نطبع محتوى الكتلة الذي عرّفته الصفحة الفرعية إن وُجد، وإلا المحتوى الافتراضي المكتوب بين `block()` و`endblock()` في القالب الأساسي نفسه (السطر 71).
  - **داخل صفحة فرعية**: نحفظ المحتوى في `$blocks`، إلا إن كان محفوظاً من قبل (السطر 72). لماذا؟ في سلسلة وراثة (صفحة ← قالب وسيط ← قالب أساسي)، الصفحة تُعرض أولاً، وتعريفها للكتلة يجب أن يغلب تعريف القالب الوسيط.

@file app/core/View.php 77-103

دوال قصيرة نستعملها في القوالب بدل كتابة `View::` في كل مرة:

| الدالة | عملها |
|---|---|
| `extend('base/base')` | الصفحة الحالية ترث هذا القالب |
| `block('content')` و`endblock()` | بداية الكتلة ونهايتها |
| `block_content('inline_messages')` | محتوى كتلة عرّفتها الصفحة الفرعية كنص دون طباعته. مثلاً: القالب الأساسي يعرض رسائل التنبيه فقط إن لم تعرّف الصفحة كتلة `inline_messages` تعرضها فيها بنفسها |
| `view_path('news/news_list')` | المسار الكامل للقالب: `app/views/news/news_list.php` |

## تجربة المحرك

لنجرّب قبل كتابة القالب الحقيقي. أنشئ مجلداً مؤقتاً `app/views/test/` وفيه ملفان:

```php app/views/test/layout.php (ملف مؤقت)
<!DOCTYPE html>
<html lang="ar" dir="rtl">
<head>
    <meta charset="utf-8">
    <title><?php block('title'); ?>عنوان افتراضي<?php endblock(); ?></title>
</head>
<body style="font-family: Tahoma; margin: 0">
    <header style="background: #8cc040; color: #fff; padding: 15px">رأس مشترك لكل الصفحات</header>
    <main style="padding: 20px">
        <?php block('content'); ?><p>لا يوجد محتوى</p><?php endblock(); ?>
    </main>
    <footer style="background: #2c3e50; color: #fff; padding: 15px">جميع الحقوق محفوظة <?= e($year) ?></footer>
</body>
</html>
```

```php app/views/test/page.php (ملف مؤقت)
<?php extend('test/layout'); ?>

<?php block('title'); ?>صفحة التجربة<?php endblock(); ?>

<?php block('content'); ?>
<h2>مرحباً يا <?= e($name) ?></h2>
<ul>
    <?php foreach ($services as $service): ?>
        <li><?= e($service) ?></li>
    <?php endforeach; ?>
</ul>
<?php endblock(); ?>
```

ثم استبدل محتوى `hello.php`:

```php hello.php (ملف مؤقت)
<?php
require __DIR__ . '/app/bootstrap.php';

echo View::render('test/page', [
    'name'     => 'زائر سطيف',
    'services' => ['الإيواء', 'الإطعام', 'النقل', '<b>المنحة</b>'],
    'year'     => date('Y'),
]);
```

افتح `hello.php`. سترى الرأس الأخضر، ثم «مرحباً يا زائر سطيف» وقائمة الخدمات، ثم التذييل، وعنوان التبويب «صفحة التجربة». ولاحظ أن العنصر الأخير يظهر كما هو `<b>المنحة</b>` ولا يصبح عريضاً، لأن `e()` هرّبته.

::: try
1. احذف كتلة `title` من `page.php`: سيصبح عنوان التبويب «عنوان افتراضي».
2. احذف كتلة `content` كلها: سيظهر «لا يوجد محتوى».
3. اكتب جملة خارج الكتل في `page.php`: لن تظهر في أي مكان.
:::

## صفحات الأخطاء

أنشئ المجلد `app/views/errors/`. كل صفحات الأخطاء (عدا 500) تتشارك تصميماً واحداً، فنكتبه مرة واحدة في `_error.php` (الشرطة السفلية في أول الاسم تعني «جزء مشترك لا يُعرض وحده»):

@file app/views/errors/_error.php

- يرث القالب الأساسي `base/base` (سنكتبه في الفصل 14)، فتظهر صفحة الخطأ بشريط التنقل والتذييل كبقية الموقع.
- يعرض رمز الخطأ وأيقونة Font Awesome وعنواناً ونصاً، من أربعة متغيرات: `$error_code` و`$error_icon` و`$error_title` و`$error_text`.
- زر «رجوع» يستعمل `javascript:history.back()` ليعود المتصفح خطوة إلى الوراء.

ثم ملف قصير لكل خطأ، يضبط المتغيرات الأربعة ثم يستدعي الجزء المشترك:

@file app/views/errors/404.php

@file app/views/errors/403.php

@file app/views/errors/405.php

@file app/views/errors/403_csrf.php

- `include` تنفّذ الملف الآخر **في النطاق نفسه**، فيرى `_error.php` المتغيرات التي ضبطناها.
- `$message ?: 'نص افتراضي'`: إن مرّرنا رسالة مع الخطأ (`abort(404, 'الخبر غير موجود')`) تظهر هي، وإلا النص الافتراضي. نتذكر من `bootstrap.php` أن معالج الأخطاء يمرر `['message' => $e->getMessage()]`.
- خطأ `403_csrf` يُعرض حين يُرسل نموذج برمز CSRF خاطئ أو منتهٍ (مثلاً: ترك الطالب الصفحة مفتوحة يومين ثم أرسل النموذج بعد انتهاء جلسته).

### صفحة الخطأ 500

الخطأ 500 يعني أن شيئاً انكسر في الكود أو في قاعدة البيانات. ربما الخلل في القالب الأساسي نفسه أو في الاتصال بقاعدة البيانات، لذلك صفحته **مستقلة تماماً**: لا ترث شيئاً ولا تستعمل قاعدة البيانات ولا ملفات خارجية:

@file app/views/errors/500.php

- **السطر 22**: تفاصيل الخطأ تظهر فقط إن مُرّر `$exception`، ومعالج الأخطاء لا يمرره إلا في وضع التطوير (`is_debug()`). الزائر العادي على الموقع الحقيقي يرى الاعتذار فقط، لأن تفاصيل الأخطاء تكشف معلومات عن الخادم قد يستغلها مهاجم.
- **الأسطر 25–28**: اسم صنف الاستثناء ورسالته، ثم الملف والسطر، ثم **مسار الاستدعاءات** (stack trace): سلسلة الدوال التي استُدعيت حتى وقع الخطأ، وهي أهم أداة لديك لإيجاد سببه.

## تجربة صفحة 500

أضف هذا السطر في آخر `hello.php`:

```php
throw new RuntimeException('هذا خطأ تجريبي');
```

حدّث الصفحة: ستظهر صفحة «500 - حدث خطأ في الخادم»، وتحتها في المربع الأحمر `RuntimeException: هذا خطأ تجريبي` ثم الملف ورقم السطر. هذا لأننا على `localhost` فوضع التطوير مفعّل تلقائياً. احذف السطر بعد التجربة.

::: note
لن تظهر صفحة 404 الجميلة بعد، بل `<h1>404</h1>` بسيطة، لأنها ترث `base/base` الذي سنكتبه في الفصل 14، وتحتاج معرفة المستخدم الحالي (الفصل 13). معالج الأخطاء في `bootstrap.php` مصمَّم ليعرض هذه النسخة البسيطة عندما تفشل الصفحة الكاملة.
:::

بعد انتهاء التجارب احذف المجلد `app/views/test/`.

::: summary
- القالب ملف HTML بأقل قدر من PHP: `<?= e() ?>` والصيغة البديلة لـ `if` و`foreach`.
- الصفحة ترث قالباً أساسياً بـ `extend()` وتملأ كتله بـ `block()` و`endblock()`.
- `View::render()` تعرض الصفحة ثم سلسلة قوالبها الأساسية، وتُرجع HTML النهائي.
- `extract()` تحوّل مصفوفة السياق إلى متغيرات داخل القالب.
- صفحات 403 و404 و405 تتشارك `_error.php`، أما 500 فمستقلة تماماً ولا تُظهر التفاصيل إلا في وضع التطوير.
:::
