# تصميم قاعدة البيانات

::: intro
قبل أن نبرمج أي صفحة، نقرر **ماذا سنخزّن وكيف**. في هذا الفصل نكتب الملف `database/schema.sql` الذي يُنشئ كل جداول الموقع (27 جدولاً)، ونفهم دور كل جدول وكل عمود، ثم نستورد بيانات الموقع الحقيقية (الأخبار، المصالح، الإقامات...) من الملف `data.sql`.
:::

## نظرة عامة على الجداول

كل قسم من الموقع له جدول أو أكثر. هذا الجدول خريطة لما سنبنيه:

| القسم | الجداول | ماذا تخزّن |
|---|---|---|
| المستخدمون | `users` | حسابات الدخول: الطلبة والموظفون والمدير |
| الصفحة الرئيسية | `sliders`، `statistics`، `director_words`، `organization_structures`، `directorate_histories` | صور السلايدر، أرقام الإحصائيات، كلمة المدير، الهيكل التنظيمي، تاريخ المديرية |
| الأخبار | `news`، `news_images`، `latest_news` | الأخبار وصور معرض كل خبر، وبطاقات «آخر المستجدات» |
| النشاطات | `activities`، `activity_images` | النشاطات الثقافية والرياضية وصورها |
| الإقامات | `cites`، `cite_images` | الإقامات الجامعية وصورها |
| المصالح | `departements` | مصالح المديرية |
| الخدمات | `services` | خدمات النقل والإيواء والإطعام والمنحة |
| الاتصال | `contact_messages` | رسائل نموذج «اتصل بنا» |
| التحميلات | `download_files` | الاستمارات والأدلة القابلة للتحميل |
| الأسئلة الشائعة | `faq_categories`، `faqs` | تصنيفات الأسئلة والأسئلة مع أجوبتها |
| الإشعارات العامة | `notifications` | الإعلانات التي تظهر في الشريط أعلى كل الصفحات |
| الزوار | `site_visits`، `site_statistics` | سجل الزيارات والعدّادات الإجمالية |
| فضاء الطالب | `student_profiles`، `application_types`، `student_applications`، `application_documents`، `student_notifications` | ملفات الطلبة، أنواع الطلبات، الطلبات، الوثائق المرفقة، إشعارات كل طالب |

::: note
ستلاحظ أعمدة تتكرر في أغلب الجداول، وفهمها مرة واحدة يكفي:

- `id`: المفتاح الأساسي، رقم يزيد تلقائياً.
- `slug`: نسخة من العنوان صالحة للروابط، مثل `ftth-lmktb` في الرابط `/news/ftth-lmktb/`. سنولّدها تلقائياً من العنوان.
- `is_active`: هل يظهر العنصر في الموقع؟ (1 نعم، 0 لا). بهذا تُخفي الإدارة عنصراً دون حذفه.
- `order` أو `display_order`: رقم يحدد ترتيب الظهور، الأصغر أولاً.
- `created_at` و`updated_at`: تاريخ الإنشاء وتاريخ آخر تعديل.
- `views_count`: عدد المشاهدات.
:::

## إنشاء قاعدة البيانات

1. افتح `http://localhost/phpmyadmin`.
2. اضغط **New** (جديد) في القائمة اليسرى.
3. اكتب اسم قاعدة البيانات: `dou_setif` (نفس الاسم في `config.php`).
4. اختر الترتيب (Collation): **utf8mb4_unicode_ci**.
5. اضغط **Create**.

أو نفّذ في تبويب SQL:

```sql
CREATE DATABASE dou_setif CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

## كتابة الملف schema.sql

أنشئ الملف `database/schema.sql`. سنكتبه جدولاً بعد جدول، وفي آخر الفصل نستورده دفعة واحدة.

### الرأس وحذف الجداول القديمة

@file database/schema.sql 1-42

- **السطر 12** `SET NAMES utf8mb4`: الاتصال نفسه بترميز utf8mb4، حتى تصل الحروف العربية في الملف سليمة.
- **السطر 13**: نعطّل مؤقتاً فحص المفاتيح الأجنبية، لأننا سنحذف الجداول وننشئها بترتيب قد يسبق فيه جدولٌ الجدولَ الذي يشير إليه.
- **السطر 14**: المنطقة الزمنية للجلسة +01:00 (توقيت الجزائر)، فتُحسب `CURRENT_TIMESTAMP` بالساعة الصحيحة.
- **الأسطر 16–42**: نحذف كل الجداول إن كانت موجودة (`IF EXISTS` تمنع الخطأ إن لم تكن). هكذا يمكن إعادة استيراد الملف في أي وقت للبدء من جديد.

::: warning
بسبب هذه الأسطر، استيراد `schema.sql` على قاعدة بيانات فيها بيانات **يمسح كل شيء**. لا تستورده على الموقع الحقيقي بعد أن يبدأ الطلبة في استعماله، إلا بعد أخذ نسخة احتياطية.
:::

### جدول المستخدمين

@file database/schema.sql 44-61

| العمود | دوره |
|---|---|
| `username` | اسم الدخول، فريد (`UNIQUE`). للطلبة هو رقم التسجيل الجامعي |
| `password` | كلمة المرور **مشفّرة** (hash) وليست كما كتبها المستخدم، و255 حرفاً تكفي لكل خوارزميات التشفير |
| `email`، `first_name`، `last_name` | البريد والاسم واللقب |
| `is_staff` | موظف: يدخل لوحة متابعة الطلبات ولوحة الإدارة |
| `is_superuser` | مدير عام: كل الصلاحيات، بما فيها إدارة المستخدمين |
| `is_active` | الحساب مفعّل؟ الحساب المعطّل لا يستطيع الدخول |
| `last_login`، `date_joined` | آخر دخول وتاريخ التسجيل |

`COMMENT '...'` ملاحظة نصية تُحفظ مع العمود وتظهر في phpMyAdmin، لا تؤثر على العمل.

### جداول الصفحة الرئيسية

@file database/schema.sql 63-124

- **`sliders`**: صور السلايدر في أعلى الصفحة الرئيسية. لكل شريحة عنوان (`title`) وعنوان فرعي (`subtitle`) وصورة (`image` يخزّن **مسار** الصورة داخل `uploads`)، ورابط اختياري (`link`) مع نص الزر (`button_text`).
- **`statistics`**: الأرقام التي تظهر في قسم الإحصائيات (عدد الطلبة، الإقامات...): أيقونة Font Awesome (`icon` مثل `fa-users`)، والرقم، والتسمية.
- **`director_words`**: «كلمة المدير»: اسمه، ومنصبه (بقيمة افتراضية `مدير الخدمات الجامعية`)، وصورته، وعنوان الكلمة ونصها (`MEDIUMTEXT` لأن النص قد يكون طويلاً بتنسيق HTML)، وصورة التوقيع.
- **`organization_structures`**: صفحة الهيكل التنظيمي: وصف، وصورة المخطط (`organization_chart`)، ومحتوى.
- **`directorate_histories`**: صفحة تاريخ المديرية: مقدمة، ومحتوى، وصورة، وسنة التأسيس.

هذه الجداول الثلاثة الأخيرة يُستعمل منها عادة صف واحد مفعّل (آخر واحد).

### جداول الأخبار

@file database/schema.sql 126-172

جدول **`news`** أغنى جدول في الموقع:

| العمود | دوره |
|---|---|
| `title`، `slug` | العنوان ونسخته للرابط (فريدة) |
| `summary`، `content` | الملخص (يظهر في القوائم) والمحتوى الكامل |
| `main_image` | الصورة الرئيسية (اختيارية: `NULL`) |
| `author_id` | كاتب الخبر، مفتاح أجنبي إلى `users` |
| `published_date` | تاريخ النشر |
| `status` | الحالة: `draft` مسودة، `published` منشور، `archived` مؤرشف |
| `is_featured` | خبر مميز |
| `show_in_ticker` | يظهر في **شريط الأخبار المتحرك** في الرئيسية |

- **السطر 147**: فهرس مركّب على عمودين `(status, published_date)`، لأن أكثر استعلام سنكتبه هو «الأخبار المنشورة مرتبة بالتاريخ»، والفهرس يجعله سريعاً حتى مع آلاف الأخبار.
- **السطر 148**: المفتاح الأجنبي `fk_news_author` مع `ON DELETE SET NULL`: إن حُذف حساب الكاتب يبقى الخبر.
- **السطر 149** `ROW_FORMAT=DYNAMIC`: صيغة تخزين تسمح بفهرس فريد على `VARCHAR(300)` بترميز utf8mb4 (حتى 1200 بايت)، فالصيغ القديمة لا تقبل فهارس أطول من 767 بايت.
- **`news_images`**: صور معرض الخبر، كل صورة مرتبطة بخبر عبر `news_id` مع `ON DELETE CASCADE` (حذف الخبر يحذف صوره).
- **`latest_news`**: بطاقات «آخر المستجدات» في الرئيسية: وصف وصورة ورابط.

### جداول النشاطات

@file database/schema.sql 174-210

النشاط له نوع (`activity_type`): رياضي `sport`، ثقافي `culture`، علمي `scientific`، اجتماعي `social`، فني `artistic`، أو آخر `other`. نخزّن **الرمز الإنجليزي القصير** في قاعدة البيانات، ونعرض الاسم العربي في الصفحات (سنعرّف هذه الترجمة في النماذج). ولكل نشاط تاريخ (`DATE`) ومكان ومنظِّم وعدد مشاركين، وصور في `activity_images`.

::: why
لماذا نخزّن `sport` بدل «رياضي»؟ لأن الرمز ثابت لا يتغير، بينما قد نغيّر التسمية المعروضة يوماً («رياضة» بدل «رياضي») دون أن نحتاج تعديل آلاف الصفوف. كما أن المقارنة بالرموز في الكود أسهل وأقل عرضة لأخطاء الإملاء.
:::

### جداول الإقامات الجامعية

@file database/schema.sql 212-243

الإقامة (`cites`): الاسم (فريد)، والوصف، والصورة، والعنوان، وطاقة الاستيعاب (`capacity`)، والهاتف. وصور كل إقامة في `cite_images`.

### جدول المصالح

@file database/schema.sql 245-265

مصالح المديرية (مصلحة المنح، مصلحة الإيواء...): الاسم، والوصف، والصورة، ورئيس المصلحة (`head_of_department`)، ووسائل الاتصال.

### جدول الخدمات

@file database/schema.sql 267-290

نوع الخدمة (`service_type`) أحد أربعة: النقل `transport`، الإيواء `housing`، الإطعام `catering`، المنحة `scholarship`. ولكل خدمة وصف قصير ومفصّل، وأيقونة (افتراضياً `fa-info-circle`)، والشروط (`requirements`)، وطريقة التقديم (`how_to_apply`)، ومعلومات الاتصال. و`featured` لإبراز الخدمة.

### جدول رسائل الاتصال

@file database/schema.sql 292-310

رسالة من نموذج «اتصل بنا»: اسم المرسل وبريده وهاتفه، والموضوع (`subject` من قائمة: عام، نقل، إيواء، إطعام، منحة، شكوى، اقتراح، آخر)، ونص الرسالة. ثم حقول تستعملها الإدارة: `is_read` (قُرئت؟)، `is_replied` (تم الرد؟)، `admin_notes` (ملاحظات داخلية). و`ip_address` عنوان المرسل، و`VARCHAR(45)` تكفي لأطول عنوان IPv6.

### جدول مركز التحميلات

@file database/schema.sql 312-332

ملف للتحميل: العنوان، والوصف، والتصنيف (`category`: استمارات المنحة، الإيواء، النقل، الإطعام، أدلة، قوانين، تقارير، أخرى)، ومسار الملف، وحجمه بالبايت (`file_size`)، وعدد مرات تحميله (`downloads_count`).

### جداول الأسئلة الشائعة

@file database/schema.sql 334-359

تصنيف (`faq_categories`) بأيقونة، وأسئلة (`faqs`) كل سؤال ينتمي لتصنيف عبر `category_id`. حذف التصنيف يحذف أسئلته (`CASCADE`).

### جدول الإشعارات العامة

@file database/schema.sql 361-380

الإعلان الذي يظهر في شريط ملوّن أعلى كل الصفحات:

- `notification_type`: اللون (`info` أزرق، `success` أخضر، `warning` برتقالي، `danger` أحمر، `primary`).
- `link` و`link_text`: رابط اختياري ونصه (افتراضياً «المزيد»).
- `start_date` و`end_date`: فترة الظهور. الإشعار يظهر تلقائياً من تاريخ البداية ويختفي بعد تاريخ النهاية (أو لا يختفي إن كانت `NULL`).
- `is_dismissible`: هل يستطيع الزائر إغلاقه؟
- `priority`: الأولوية، الأكبر يظهر أولاً.

### جداول إحصائيات الزوار

@file database/schema.sql 382-402

- **`site_visits`**: سطر لكل زيارة: عنوان IP، والمتصفح (`user_agent`)، والصفحة، والوقت. الفهرس `(ip_address, visited_at)` يسرّع السؤال «هل زار هذا العنوان الموقع اليوم؟» الذي نطرحه مع كل زيارة.
- **`site_statistics`**: صف واحد فقط يحمل العدّادين الإجماليين: عدد الزوار المختلفين، وعدد مشاهدات الصفحات.

### جداول فضاء الطالب

@file database/schema.sql 404-432

**`student_profiles`**: المعلومات الجامعية للطالب، مرتبطة بحسابه في `users` عبر `user_id` (فريد: لكل حساب ملف واحد). أهم الأعمدة: رقم التسجيل (`registration_number`، فريد)، والاسم بالعربية، وتاريخ ومكان الميلاد، والجنس (`CHAR(1)`: `M` أو `F`)، والهاتف، والولاية، والكلية والقسم، والسنة الدراسية (`1`، `2`، `3`، `M1`، `M2`، `D`)، والمعدل (`DECIMAL(4,2)` مثل `14.75`)، والصورة الشخصية، و`is_verified` (تحققت منه الإدارة).

@file database/schema.sql 434-444

**`application_types`**: أنواع الطلبات التي يستطيع الطالب تقديمها (طلب إيواء، طلب منحة، طلب نقل...). لكل نوع أيقونة ولون (`#3498db`) وقائمة الوثائق المطلوبة (`required_documents`).

@file database/schema.sql 446-466

**`student_applications`**: قلب فضاء الطالب. كل طلب:

| العمود | دوره |
|---|---|
| `student_id` | صاحب الطلب (← `student_profiles`) |
| `application_type_id` | نوع الطلب (← `application_types`) |
| `application_number` | رقم فريد يُولَّد تلقائياً: السنة ثم رقم تسلسلي من 5 أرقام، مثل `202500012` |
| `status` | الحالة: `pending` قيد الانتظار، `under_review` قيد المراجعة، `approved` معتمد، `rejected` مرفوض، `cancelled` ملغي |
| `details` | تفاصيل يكتبها الطالب |
| `admin_notes` | ملاحظات الموظف للطالب |
| `submitted_at` | تاريخ التقديم |
| `reviewed_at`، `reviewed_by_id` | متى ومن راجع الطلب (← `users`) |

لاحظ الفهارس الثلاثة: على `(student_id, submitted_at)` لعرض طلبات الطالب بالترتيب، وعلى `status` لفلترة الطلبات في لوحة الموظفين، وعلى `submitted_at` للإحصائيات.

@file database/schema.sql 468-494

- **`application_documents`**: الوثائق المرفقة بكل طلب (اسم الوثيقة ومسار الملف). حذف الطلب يحذف سجلات وثائقه.
- **`student_notifications`**: إشعارات خاصة بكل طالب («تم قبول طلبك»): عنوان، ونص، ورابط، ونوع (لون)، و`is_read` و`read_at`. الفهرس `(student_id, is_read, created_at)` يجعل حساب «عدد الإشعارات غير المقروءة» فورياً، وسنحسبه في كل صفحة يفتحها الطالب.
- **السطر 494**: إعادة تفعيل فحص المفاتيح الأجنبية.

## استيراد الجداول والبيانات

نسخة المشروع المرجعية `dou-setif-php.zip` تحتوي، إضافة إلى الكود، على ملف البيانات `database/data.sql`: كل محتوى الموقع الحقيقي (الأخبار، المصالح، الإقامات، الخدمات، الأسئلة...) وحسابات تجريبية. انسخه إلى مجلد `database` في مشروعك، وانسخ معه محتوى مجلد `uploads` (الصور المرفوعة).

### من phpMyAdmin

1. اختر قاعدة البيانات `dou_setif` من القائمة اليسرى.
2. اضغط تبويب **Import** (استيراد).
3. **Choose File** ← اختر `database/schema.sql` ← اضغط **Import** (أو Go) أسفل الصفحة.
4. يجب أن تظهر رسالة خضراء، وتظهر الجداول الـ 27 في القائمة اليسرى.
5. كرّر الخطوات نفسها مع `database/data.sql`.

### أو من سطر الأوامر

```cmd
cd C:\xampp\htdocs\dou-setif
C:\xampp\mysql\bin\mysql.exe -u root dou_setif < database\schema.sql
C:\xampp\mysql\bin\mysql.exe -u root dou_setif < database\data.sql
```

::: warning الترتيب مهم
استورد `schema.sql` **أولاً** ثم `data.sql`. الأول ينشئ الجداول فارغة، والثاني يملؤها. وإن أعدت استيراد `schema.sql` لاحقاً فستُحذف كل البيانات وتحتاج إعادة استيراد `data.sql`.
:::

## التحقق من البيانات

في تبويب **SQL** لقاعدة البيانات `dou_setif` نفّذ:

```sql
SELECT COUNT(*) FROM news;
SELECT id, title, status FROM news ORDER BY published_date DESC LIMIT 5;
SELECT name FROM departements WHERE is_active = 1 ORDER BY `order`;
SELECT username, is_staff, is_superuser FROM users;
```

إن ظهرت النتائج والعناوين العربية سليمة فقاعدة البيانات جاهزة.

::: note
كلمات مرور الحسابات الموجودة في `data.sql` مشفّرة ولا نعرفها. لا تقلق: في الفصل 21 سنكتب أداة صغيرة لإنشاء حساب مدير بكلمة المرور التي تختارها، وفي فضاء الطالب يمكنك تسجيل حساب طالب جديد بنفسك.
:::

::: try
افتح الجدول `users` في phpMyAdmin (**Browse**) وانظر إلى عمود `password`. ستجد نصوصاً طويلة تبدأ بـ `pbkdf2_sha256$`: هذه كلمات مرور مشفّرة من النسخة القديمة للموقع. سنرى في الفصل 13 كيف يتعرّف عليها موقعنا ويحوّلها تلقائياً إلى التشفير الحديث عند أول دخول.
:::

::: summary
- قاعدة البيانات `dou_setif` بترتيب `utf8mb4_unicode_ci` وفيها 27 جدولاً.
